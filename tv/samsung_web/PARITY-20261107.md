# Samsung i Android — sprawdzenie 2026-11-07

Zakres: zgłoszony powrót na początek po dłuższym używaniu, zatrzymanie live z
InvalidState, wolne grafiki i `EPG:RETRY SIZE` dla automatycznego EPG M3U.
Przegląd wykonano według skills systematic-debugging, test-driven-development,
requesting-code-review i verification-before-completion, z niezależnym
przeglądem poprawek oraz porównaniem obu platform.

## Zmiany 0.1.34

| Obszar | Wynik |
| --- | --- |
| Katalog po 24 h | Oddzielna instancja źródła przygotowuje pełny katalog. Stary katalog pozostaje dostępny. Publikacja czeka na aktywne odczyty, w tym EPG, szczegóły i rozwiązywanie adresu odtwarzania. Nie zatrzymuje odtwarzacza ani nie otwiera Home. |
| Nowe kanały i nawigacja | Nowa lista jest przekazywana do interfejsu. Zachowany jest ekran, strona, przewinięcie i fokus kanału/kategorii/programu EPG. Otwarta lista filmów/seriali zachowuje karty; nowy katalog zobaczy przy kolejnym wejściu. |
| Błąd pobrania katalogu | Stary katalog pozostaje. Następna automatyczna próba po godzinie, jak w `lib/screens/home_shell.dart`; pojedynczy błąd nie wyłącza aktualizacji do restartu. |
| InvalidState w działającym live | Ograniczone odzyskiwanie sesji zamiast natychmiastowego zakończenia. Błąd `stop` już utraconej sesji nie blokuje ponownego otwarcia, jeżeli `close` się powiedzie. Błędy zamknięcia i odmowy dostawcy nadal są obsługiwane. |
| Długa sesja live | 30 sekund obserwowanego, ciągłego postępu odtwarzania odnawia budżet odzyskiwania, podobnie do Android `LiveReconnectBudget`. Sam upływ czasu, buforowanie, powtarzający się zegar i pojedynczy skok pozycji go nie odnawiają. Kolejne awarie bez zdrowego odtwarzania nadal mają limit. |
| Wygaszacz ekranu | Zwykłe zmiany stanu czekają na zakończenie poprzedniego żądania natywnego. |
| Grafiki | Usunięto sztuczne opóźnienie jednej sekundy na serwer. Pozostają dwa równoległe transfery, pobieranie przy widocznym obszarze, ochrona po błędach i limit czasu. |

## Pozostałe różnice

1. **Duże EPG M3U — adapter dyskowy dodany w 0.1.35.** Samsung pobiera do
   prywatnego katalogu aplikacji i czyta plik porcjami do 64 KiB. Gzip jest
   rozpakowywany w Workerze z ograniczonym buforem, z kontrolą CRC/rozmiaru.
   Limity pracy odpowiadają Androidowi: 512 MiB pobranego pliku i 4 GiB po
   dekodowaniu. Cache mieści osiem plików / 768 MiB, a stare EPG pozostaje do
   czasu pełnej walidacji i zatwierdzenia nowego. Nieprawidłowy XML, HTML,
   pusty HTTP 200 i ucięty gzip nie zastępują dobrego pliku. Klucze cache
   obejmują profil i źródło. Zachowano blokady i terminy ponownych prób.
   Nie dodano zgadywania adresów ani odpytywania API Xtream dla źródła M3U.
2. **Różnica platformowa IO.** Implementacja używa publicznych API Tizena:
   [Download API](https://developer.samsung.com/smarttv/develop/guides/data-handling/downloading-data.html)
   i [FileStream.readBytes](https://developer.samsung.com/smarttv/develop/api-references/tizen-web-device-api-references/filesystem-api.html).
   Wymagane uprawnienie download dodano do manifestu. Jeśli natywne API są
   niedostępne, pozostaje dotychczasowy ograniczony adapter przeglądarkowy
   32 MiB (48/64 MiB wyłącznie z potwierdzonym zapasem PMS). Zachowanie API
   i ilość miejsca na konkretnym TV wymagają próby sprzętowej.
3. **Grafiki.** Android ma 12 równoległych transferów, trwały cache plików i
   dobór wielkości dekodowania (`lib/data/provider_image_cache.dart`). Samsung
   ma dwa transfery i cache przeglądarki; miniatury zmniejsza dla rozpoznanych
   URL TMDB. Dwa wolne serwery nadal mogą zająć jego oba sloty.
4. **Odtwarzacz.** Android używa ExoPlayer i obserwuje również renderowanie
   klatek; Samsung AVPlay obserwuje zegar i zdarzenia. Samsung ponawia obecny
   URL, a Android może uzyskać nowy locator; ma to znaczenie dla krótkotrwałych
   tokenów Stalkera. Zakończenie live przez natywne EOF również ma odrębną
   obsługę. Tych różnic nie zmieniano.
5. **Start procesu.** Poprawki dotyczą aktualizacji w żyjącej aplikacji.
   Uruchomienie nowego procesu nadal przechodzi zwykłą ścieżką startową.
   Brak logu z TV nie pozwala potwierdzić, czy zgłoszony powrót na Home był
   aktualizacją interfejsu, czy zamknięciem i ponownym uruchomieniem procesu.

## Weryfikacja

- Odtworzono błędy testami przed poprawką: brak publikacji nowych kanałów,
  InvalidState, utrata budżetu po zdrowych okresach, opóźnienie grafik,
  anulowanie szczegółów przy publikacji oraz utrata pozycji/fokusu.
- Przebudowano rdzeń z obecnych źródeł oraz payload 0.1.35. Build sprawdził
  zgodność hashy, składnię ES5 i ograniczenia CSS starego Tizena.
- `npm test`: **432/432**, bez pominiętych testów. Log:
  `app/output/samsung-fixes-20261107/disk-suite-final.log` względem katalogu głównego
  workspace. Testy używają jednej aktualnej generacji rdzenia i pakietu.
- Istniejący `test/ui_browser_qa.js`: **12 etapów zakończonych powodzeniem**,
  brak błędów runtime przeglądarki. Sprawdzono m.in. układ 720p/1080p, pilot,
  listę 161 kanałów, przewijanie EPG, podgląd/fullscreen, źródła M3U/Xtream,
  filmy/seriale, profile i PIN. SDK Samsunga oraz dostawca były zastępcze.
- Nowy `disk_epg_browser_qa.js`: Worker z pakietu 0.1.35 odczytał i rozpakował
  gzip, zatwierdził plik i ponownie użył go po restarcie Workera bez pobrania.
  Natywna granica plikowa była zastępcza. Poprzedni test całego UI dotyczył
  pakietu 0.1.34.
- XMLTV i gzip o ponad 40 MiB danych rozpakowanych przeszły przez rdzeń przy
  limicie sterty procesu 128 MiB. Testy potwierdzają porcje, walidację XMLTV,
  błędy CRC/ucięcia, izolację profili i zachowanie poprzedniej generacji.
- Nie wykonano instalacji, podpisania ani wielogodzinnej próby na fizycznym TV.
  Testy SDK/HTTP używają granic zastępczych; nie kwalifikują dekodera,
  dostępnej pamięci i rzeczywistego dostawcy EPG.
